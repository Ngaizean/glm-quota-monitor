# 账号与设备分发

Codex 账号分为官方订阅与中转站两类，沿用 `accounts` 的账号 ID；类型、地址和默认模型存入 `codex_profiles`，凭据存入系统凭据库。额度查询以账号为单位，不再依赖本机当前服务商。

账号管理提供登录、导入、添加中转账号、编辑默认配置、应用到本机、修复旧会话和关联设备状态。登录走 codex CLI 的浏览器 OAuth；导入自动识别本机 auth.json 的中转或官方身份。远程设备独立管理 SSH 绑定、模型覆盖与自动同步。云端同步独立管理发布者、接收者、Gist 和分发账号。

账号切换会把所选账号的完整配置覆盖本机 `~/.codex`（auth.json + config.toml，原文件备份为 `.bak-quota-monitor`，config 写失败时回滚 auth）。切换会话修复：旧会话 rollout 首行 session_meta 记录了创建时的 `model_provider`，与新账号不一致会导致 resume 失败（典型现象是官方订阅切到中转站后旧对话打不开）。切换和手动「修复旧会话」都会把扫描到的旧 provider 改写为当前账号对应值（官方 `openai`、中转 `quota_monitor`、旧运行时路径 `sub2api`），改动前整文件备份到 `~/.codex/session_repair_backup/`。旧格式会话（无该字段）跳过；修复只保证 provider 可解析，不校验 API 可用性。

设备默认绑定明确账号；本机切换不改变绑定。显式选择“跟随本机账号”时才跟随。设备模型和推理强度留空时继承账号设置。解除绑定只停止管理，不删除远端文件。同步前先检测远端 `codex` 是否安装（`command -v`），未安装时报错并在界面显示不支持；Claude Code 远程同样有安装检测。

自动同步每五分钟检查设备文件；与目标一致时不重复写入，远端自行修改后下一轮会恢复目标配置。状态“文件已校验”表示写入后回读一致，不代表已经重启远端 Codex 进程或验证模型请求。

SSH 目标需要 Unix shell 和 Python 3.8 以上。免密登录或保存的 SSH 密码支持后台同步。配置与凭据先暂存，再替换；替换失败恢复旧文件。备份保留在目标 `.codex` 目录，带 `.bak-quota-monitor` 后缀。

云端 Gist 同步支持一次发布多个账号（官方订阅与中转站可混选，存于 `codex_cloud_accounts`）。单账号沿用旧版单 Bundle 格式，两个及以上账号使用 v2 批量格式 `{"version":2,"accounts":[...]}`；接收端一次拉取并全部落地为 `synced_` 前缀账号，本机当前账号在批次中时刷新它，否则不改变本机配置，旧版单 Bundle 与纯凭据格式仍可读。发布者自动上传按整个账号集合的指纹判重。同一个 Gist 后续发布另一批账号时，旧账号档案仍保留。新格式需要收发两端都升级；后台凭据刷新仅在发布者执行。

首次升级保持已有官方账号 ID，归档本机尚未导入的官方凭据，把旧的单一中转配置迁入账号列表。原本启用自动覆盖的设备绑定迁移时的账号；不再隐式跟随本机切换。迁移不删除历史数据或改写本机运行配置。

验证入口：`npm run test:run`、`npm run build`、`cargo test --lib --locked`。后端测试包含双文件回滚、幂等回读、配置保留、加密包往返、会话 provider 修复与备份、多账号选择回落和设备绑定隔离；前端测试覆盖绑定失败、未安装禁用绑定、未绑定禁止推送和云端多选发布。
